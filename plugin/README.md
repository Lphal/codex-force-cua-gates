# 电脑操控与浏览器门控解锁

本地强制开启 ChatGPT（Codex App）「电脑操控 / 浏览器」相关功能的 Statsig 门控读取结果，绕过**地区限制 / 组织策略**在客户端的可用性判定。

## 背景

设置页的「不可用」徽标（`settings.browserPlugin.restrictedAvailabilityDescription`：「已被你的组织停用，或在你所在地区不可用」）由应用内 Statsig 门控的本地读取结果驱动。功能执行（电脑操控、浏览器控制）本身都在本地进行，模型流量走 Codex++ 网关，不依赖 OpenAI 门控接口——所以只要客户端读取门控时返回「已开启」，功能即可用。

本拓展做的事：

1. 找到页面里所有 Statsig 客户端实例（`window.__STATSIG__`）
2. 包装 `getFeatureGate` / `checkGate`：只对设置里勾选的 gate 返回 `{ value: true, reason: "LocalOverride" }`
3. 每 3 秒兜底迟到或重建的客户端实例；配置改动后立即重新生效

**不修改任何网络请求**，不发数据，重启应用或关闭拓展即完全恢复原状。

## 设置项

| 设置 | 说明 |
|---|---|
| 电脑操控（`1506311413`） | 默认开启。设置里的 Computer use：截屏、鼠标与键盘控制 |
| 外部浏览器（`410065390`） | 默认开启。通过浏览器扩展把操作交给外部 Chrome / Edge |
| 内置浏览器 Agent（`410262010`） | 默认开启。应用内浏览器面板的 Agent 能力 |
| 其它 15 项 | 默认关闭。会话时间线、列表预取、购物卡片、广告、Work、Pages、文件库、DIL、归因、插件创作、流式重试、新手指引、消息修订等，每项标题为「中文（哈希）」 |

所有门控都是勾选框，标题格式为「中文名称（哈希）」。标有「反向」的项表示 gate 为 true 时会关闭对应功能，按需勾选。

两个入口共用同一份清单：Codex++ 管理器读 `settings.html`，ChatGPT「拓展」详情页由 `settings-panel.js` 通过 `ctx.registerSettingsPanel` 挂载。

设置入口：Codex++ 管理器 → 用户脚本 → 本拓展 → 设置；Codex 应用内「拓展」详情页也有同一份设置面板。

## 边界与注意

- **作用域是渲染进程**：覆盖设置页可用性与 UI 流程；Rust app-server 层的门控读取不受影响，由 Statsig 缓存粘性兜底（有网时拉取的配置会一直留在本地）
- 应用大版本更新后若功能重新变灰，先确认本拓展已启用；仍灰说明判定逻辑变化，需要重新逆向定位新的判定点
- 只勾选需要的门控可以最小化副作用；应用更新后哈希可能变化，需要重新对撞
- 提示：绕过地区门控违反 OpenAI 服务条款，账号风险请自行评估

## 工作原理参考

设置页判定逻辑（app.asar 反汇编结论）：不可用徽标仅在 `reason === "statsig-disabled"` 或 `"config-requirement-disabled"` 时渲染，对应三个 gate 输入（均为预哈希的 `checkGate("…")`）：

- 电脑操控 `1506311413`
- 外部浏览器 `410065390`
- 内置浏览器 Agent `410262010`

## 诊断

页面全局 `window.__forceCuaGates` 记录当前状态：

```js
{ version: "2.2.2", gates: ["1506311413", "410065390", "410262010"], patched: 1, at: 1794377267780 }
```

`gates` 是当前强制清单，`patched` 是已成功包装的 Statsig 客户端数量；两者都为空或对象不存在，说明脚本没执行到包装逻辑。开发仓库里的 `tools/probe.mjs` 会连同各 gate 的实际读取结果一起打印。
